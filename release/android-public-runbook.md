# Android 1.0.0 공개 출시 상태

2026년 10월 20일 확인. 공개 출시는 완료되지 않았다. 원본 저장소와 사용자 파일을 보존하고 별도 공개 사본에서 구현했다.

## 고정한 후보

- 저장소: https://github.com/seoleeapps/memorize-all
- 소스 SHA: `3c600c50f2a63a96976671f6bbcc47963f4ac304`
- 패키지: `com.seorilabs.memorizeall`, 버전 `1.0.0`, versionCode `3`
- Google Play 개발자: `Seolee Apps`, 개발자 ID `5547060480954653351`
- 무료, 성인 18세 이상, 콘솔의 제공 가능 국가 178개 전체 선택, 전체 출시 승인
- Firebase, 로그인, 서버와 별도 원격 분석은 추가하지 않는다. 수익모델은 기존 하단 배너 한 개다.

현재 Play 최댓값은 2이고 내부 테스트의 기존 AAB는 `0.1.1 (2)`다. 새 업로드 직전에 최댓값을 다시 확인한다. 다른 업로드로 3이 사용되었다면 새 코드와 후보를 정하고 검증한다. 기존 태그나 업로드 기록을 덮어쓰지 않는다.

## 완료한 범위

한영 지식 100개와 문제 200개를 전수 검수했다. 지식 ID, 저장 키와 schema 1을 유지했다. 빈 분야와 내부 검수 문구를 정리하고 저장 실패 복구를 확인했다. 광고 동의와 초기화 순서의 순수 로직 테스트를 통과했다.

최종 후보의 독립 L3 개발 검수에서 lint, TypeScript, Node 25개와 Python 7개, 콘텐츠 재생성 대조, 출시 소스 검사, 웹 export와 실제 브라우저 전체 흐름이 통과했다. 캡처 22개를 직접 검수했고 실행 오류는 없었다. 중앙 before-build와 before-release 검증기도 통과했다. 근거는 `docs/qa/independent-3c600c5.json`과 `release/evidence/2026-10-20/development-evidence.json`이다. 공개 QA 사본에서는 실행기 경로만 `$PLAYWRIGHT_PYTHON`으로 가렸다. 실제 로그와 캡처 38개 파일은 체크아웃 밖의 검수 보관소에 압축하고 모두 읽어 해시를 대조했다. 보관 파일 해시는 `release/evidence/2026-10-20/qa-archive-manifest.json`에 있다.

교차 코드 리뷰 2회를 마쳤다. 서명 정보를 릴리스 환경에 한정하고 `v*` 태그만 해당 환경을 사용하도록 설정했다. 저장소 secret은 0개다. 기존 활성 키와 로컬, BeeStation 백업의 복원 검증을 거쳤으며 키를 교체하지 않았다. 승인한 콘텐츠와 생성된 catalog의 일치 검사를 추가했다. 실제 변조를 거부하고 파일을 덮어쓰지 않는 회귀 테스트를 통과했다.

Play 소개와 실제 웹 실행 화면을 한국어와 영어로 저장하고 API로 다시 읽었다. 정책 선언 8개, 콘텐츠 등급, 무료 가격과 178개 국가 선택을 콘솔에서 확인했다. 데이터 보안 초안에는 Google 광고 SDK의 대략적인 위치, 앱 상호작용, 진단, 기기 또는 기타 ID를 수집과 공유로 신고했다. TLS, 계정 없음, 광고와 SDK 분석 및 부정행위 방지 용도를 기록했다. 광고 ID 선언도 같은 용도로 저장된 상태를 다시 읽었다. 별도 제품 원격 분석을 추가했다는 의미는 아니다. 페이지를 새로 연 뒤 Console CSV를 내보내 네 가지 데이터 유형과 용도 49개 응답이 저장되어 있음을 다시 대조했다. CSV 원본 해시와 선택된 답은 `release/evidence/2026-10-20/data-safety-persistence.json`에 있다.

## 현재 차단 조건

GitHub가 Actions, Pages와 Webhooks 지연을 공지했다. 최종 필수 검사는 대기 상태로 완료 여부를 확인하지 못했다. Linux 브라우저 산출물을 내려받아 여섯 시나리오 묶음의 통과와 실행 오류 0개를 확인했고 PR merge commit과 후보의 소스 트리가 같다. 하지만 전체 job 로그는 조회되지 않고 검사 상태는 대기이므로 CI를 통과로 기록하지 않았다. 새 AAB는 빌드되지 않았다.

개인정보와 지원 페이지 PR https://github.com/seorilabs/seorilabs-official/pull/79 는 필수 검사 통과 후 병합됐다. main SHA는 `ac4705e8db71710f120c53d347947d87934cfbf9`다. Pages 배포는 https://github.com/seorilabs/seorilabs-official/actions/runs/39284177459 에서 대기 중이고 네 URL은 아직 404다. 따라서 Play 개인정보 링크와 지원 사이트 입력, 데이터 보안 최종 저장이 남았다. 데이터 보안의 저장 버튼은 개인정보 링크 부재로 비활성 상태다.

AdMob 앱은 검토 필요와 광고 게재 제한 상태다. 패키지 검색에 앱이 없어 스토어 연결을 완료하지 못했다. 기존 공유 GDPR 메시지에서 Memorize All은 선택되어 있지 않고 앱 개인정보 URL도 없다. 다른 앱의 메시지는 변경하지 않았다. 공개 `app-ads.txt`는 HTTP 200이고 게시자 행이 일치하지만 이 앱의 크롤링 인증을 뜻하지 않는다. 스토어 연결 후 앱별 상태를 다시 확인한다.

## 이어서 실행할 순서

1. 앱 PR의 현재 HEAD 검사와 미해결 리뷰를 확인하고 통과 후 병합한다. 병합 SHA를 출시 후보로 택한다면 그 SHA에 맞는 개발 검수와 중앙 검증 근거를 새로 만든다.
2. Pages 실제 배포와 한국어, 영어 개인정보 및 지원 URL의 HTTP 200과 본문을 확인한다. Play 개인정보 링크와 지원 사이트, 데이터 보안 최종 저장을 마친다. AdMob 앱 개인정보 URL과 해당 앱의 지역별 동의 메시지를 설정하고 저장 상태를 다시 읽는다.
3. 최종 SHA에 `v1.0.0` 태그를 만들고 Linux 검사와 서명 빌드를 실행한다. 서명 키는 `android-release` 환경의 기존 키만 사용한다. 비밀번호와 키를 파일 출력이나 오류 로그에 넣지 않는다.
4. AAB, `SHA256SUMS`, `SOURCE_SHA`, ELF 검사 결과를 즉시 내려받는다. Actions artifact는 3일 보존이므로 업로드 전에 같은 파일을 별도 보관소에도 보존하고 SHA-256을 다시 읽어 대조한다. 아직 새 AAB가 없어 보존 완료로 기록하지 않았다.
5. 실제 AAB manifest의 패키지, 버전, versionCode, SDK, 비디버그 상태와 운영 광고 ID, 업로드 인증서 지문, bundle의 16KB 설정, 64비트 ELF와 APK zip 정렬을 정적으로 확인한다. 과거 AAB의 46개 라이브러리 통과를 새 AAB의 통과로 이어받지 않는다. RELRO는 공식 예외 조건을 적용한다.
6. 같은 해시의 AAB를 내부 테스트에 올리고 처리 결과와 정확한 버전을 다시 읽는다. 그 AAB를 프로덕션으로 올려 무료, 178개 국가와 전체 출시, 등록정보 및 정책 선언, 현재 관리형 게시 설정과 실제 오류를 확인한다. 게시 개요에서 심사를 제출하고 제출 시각, 버전과 상태를 다시 읽는다.
7. 심사 승인 후 공개 상태까지 진행하고 공개 스토어 URL과 국가를 확인한다. AdMob의 스토어 연결, 메시지, 심사와 app-ads.txt 인증을 별도로 읽는다. 실제 설치와 배너 표시는 공개 후 사용자가 확인한다.

## 미실행 범위

사용자가 에뮬레이터와 실기기 사용을 제외했다. 기기 조회, 설치, 조작, 로그와 화면 수집을 하지 않았다. 실제 UMP 메시지와 배너, Android 공유 수신과 파일 선택, Play 설치본 실행, 네이티브 글자 크기와 접근성, 16KB 런타임은 미실행이다. 새 AAB가 없어 산출물 검증, 업로드, 처리, 심사 제출, 승인과 공개도 미실행이다.

출시 원장 검사는 구조 오류 0개이고 공개 완료는 false다. 남은 단계를 미리 pass로 바꾸지 않는다. 과거 의존성 보안 권고 4종의 범위와 미수정 사유는 `docs/dependency-audit.md`에 남아 있다.
