# schema 1 이전 관심 분야 복원

이전 `0.1.1` 원본 SHA `9cbeb20dbf011cac768a4901fbc6bff862947bcd`의 catalog에는 분야 16개가 있었다. 원본 파일에서 추출한 목록을 `tests/fixtures/legacy-categories-v0.1.1.json`에 보존했다. 이전 화면의 관심 선택 버튼은 콘텐츠가 있는 5개만 표시했지만, 파일 가져오기와 로드의 검증기는 16개 ID를 허용했다. 실제 사용자 파일에서 발생했다고 주장하지 않는다. 이전 검증을 통과하는 합성 파일로 재현했다.

후보 `3c600c5`에서 제공 분야를 5개로 줄인 뒤, 이전에 허용했던 11개 ID 중 하나가 관심 목록에 있으면 `Invalid interests`가 발생한다. 저장 로드도 같은 `parseBackup`을 사용하므로 복원 화면에서 멈춘다. 기존 독립 검수의 다른 흐름 통과 기록은 보존하며 이 새 사례를 통과한 것으로 소급하지 않는다.

수정 전 선택한 회귀 테스트 3개 중 2개가 `Invalid interests`로 실패하고 알 수 없는 ID와 중복 거부 테스트만 통과했다. 실제 출력은 `docs/qa/legacy-backup/red.log`다. 명령은 다음과 같다.

```sh
node --import tsx --test --test-name-pattern='previously valid interests|only retired interests|retired interests do not' tests/learning.test.ts
```

수정은 schema 1의 과거 11개 ID만 읽기 호환 목록으로 인정한다. 지금 제공하는 관심 분야는 순서를 유지하고, 확인된 과거 선택만 제외한다. 진도, 시도 기록, 완료 기록, 언어와 학습 모드, 유효한 진행 중 세션을 보존한다. 과거 선택만 있으면 빈 관심 목록의 기존 전체 분야 학습 동작을 따른다. 알 수 없는 ID와 중복, 손상된 세션은 계속 거부한다. 저장 형식과 키는 바꾸지 않는다. 파일 읽기는 원본을 덮어쓰지 않으며 다음 사용자 저장 때 정리된 관심 목록을 쓴다. 과거 백업 가져오기를 계속 지원하기 위한 호환이며 임시 코드가 아니다.

수정 후 작성자 검사에서 lint, TypeScript, Node 28개와 Python 7개, 콘텐츠와 구조, catalog 대조가 통과했다. 웹 export와 실제 브라우저 전체 흐름도 통과했다. 새 브라우저 검사는 과거 선택이 든 파일의 재시작 복원, 다음 저장, 파일 가져오기와 재시작 뒤 진도 일치를 확인한다. 최종 SHA의 독립 L3와 중앙 검증은 별도 근거로 기록한다.

네이티브, 에뮬레이터와 실기기는 사용하지 않았다. 이 수정만으로 AAB, 업로드와 공개 상태를 통과로 바꾸지 않는다.
